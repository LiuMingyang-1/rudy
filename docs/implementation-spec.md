# Rudy 实施规格

**目标基线 1.0 · 编排能力待实现。** [README](../README.md) 负责展示项目；本文定义完整交付范围、对外行为和验收标准。当前仓库可运行的是 pi 原型。

本文固定的是用户能做什么、状态归谁、故障后如何处理。文件名、CLI 参数、依赖选择、表结构、协议编码和超时数值由实现决定。只有范围、责任边界或可观察行为变化时才更新本文，并说明取舍。

## 1. 最终要交付什么

Rudy 是单用户、自托管的 TypeScript Agent 编排应用。用户从终端交代任务，Rudy 调用 Codex 和 Claude Code，在本机或另一台已配对的机器上执行。用户可以观察进度、中断、恢复、改变执行者，最后检查工作结果并决定是否合并。

完整演示使用一个有确定复现方式的测试问题。主机上的 Partner 把请求拆成修复和审查，远程 Codex 在独立 worktree 修复。执行过程中重启主机，原任务恢复，随后由同一台 Worker 上的 Claude Code 审查。用户在 CLI 看到实际 diff、验证结果、审查意见和恢复记录，确认后合并。另演示一次 Codex → Claude Code → Codex 的同任务换手。

| 纳入范围 | 交付边界 |
| --- | --- |
| CLI 与只读 Partner | 自然语言委派、手动建任务、查询与跟进、暂停与恢复、重试、换 harness、结果确认 |
| 两种 harness | Codex、Claude Code。统一事件和控制接口，复用各自模型循环、工具和会话能力 |
| 编排与持久化 | 独立任务、串并行任务组、按时间等待、固定间隔例行任务、SQLite 任务日志 |
| 代码交付 | 已配置 Git 仓库、独立 worktree、变更与验证证据、以用户确认为前提的本地合并 |
| 跨设备 | 一台主机加一个远程 Worker，支持本机执行、能力匹配、指定设备和断线重连 |
| 上下文 | Partner 对话摘要，任务简报与 checkpoint，执行端原生项目指令和 Skills，可选 Nowledge Mem |

完整交付以 CLI 为唯一界面。Web、移动端、聊天渠道、浏览器控制、任意 DAG、通用外部事件触发、多主机高可用、原生会话跨机器迁移、自研 Agent Loop 及导入用户在 Rudy 外手动创建的历史会话，都在本次范围之外。旧 pi 原型的 CLI 和数据格式无需兼容。

## 2. 模块与数据归属

维持一个 TypeScript 应用。CLI 通过主机提交命令和订阅事件，关闭 CLI 不会停止任务。主机是调度和任务状态的唯一权威。本机 Runner 和远程 Worker 使用同一份执行契约。

| 目标目录 | 责任 |
| --- | --- |
| `src/client/` | CLI 输入、历史、进度、用户确认。通过主机查询与操作任务 |
| `src/host/` | 校验请求、状态转换、任务组、定时、选机器、执行归属和恢复决策 |
| `src/partner/` | 读取允许的任务信息，生成任务简报和计划，解释结果，管理摘要与记忆接入 |
| `src/store/` | SQLite 事务、事件和状态查询。数据库由主机管理 |
| `src/runner/` | 在执行机器准备 worktree，调用 harness，采集进度、工作区事实与交付证据 |
| `src/harness/` | 封装 Codex、Claude Code；适配启动、原生恢复、事件流、发送、停止及能力探测 |
| `src/worker/` | 配对、连接、能力上报、远程请求和断线后的执行核对 |
| `src/protocol/` | 共享任务、执行引用、事件以及主机与 Worker 之间的消息定义 |
| `test/` | 模拟 harness、临时 SQLite 和 Git 仓库、假时钟与故障测试 |

Partner 只可读取授权范围内的信息并提出编排请求。实际创建、继续、合并等操作由主机校验。Partner 和审查任务要在执行层限制写入；如果所选 harness 无法提供所需限制，则该角色启动失败。项目指令或 Agent 输出不能授予新的目录、执行权限或合并授权。

## 3. 主流程与任务语义

1. 用户提交任务。Partner 产出简报，至少包含目标、允许的仓库或工作区、范围、完成条件和约束。用户也可绕过自然语言拆解，直接创建带简报的任务。启动前由主机验证目录、执行角色、依赖和执行位置。
2. 主机持久化任务及分派决定。Runner 准备工作区，启动 harness，并将事件与原生会话引用回传。CLI 可断开后重连、查看已存历史并继续订阅。
3. 用户可追加指令。正在执行时，待处理的指令及其投递状态可查询；回复先保存，再尝试投递。结果不明的输入标明待确认，避免恢复时静默重复发送。
4. 执行 Agent 提交结果。Rudy 展示变更、验证与未完成事项，并按完成条件决定是否可以释放下游任务。失败后用户可以查看原因，并在确认原执行已停止时重试。
5. 暂停会保留任务历史、会话引用和工作区。正在执行的任务先请求中断；仅收到停止确认后才显示已暂停。取消同样要求核实停止，且保留已有改动和日志。恢复、重试和换 harness 都沿用同一个任务 ID。

**任务**是用户目标和历史。**一次执行**是某个 Runner 对该任务的一次领取，用于识别迟到事件和重复分派。**原生会话**属于特定 harness、机器和工作区；一次执行可以沿用旧会话。原生会话 ID 不能当作任务 ID。

CLI 至少能区分待执行、运行中、等待、暂停、成功、失败和取消。等待状态必须说明原因，例如依赖未完成、等待用户、等待到时、等待设备或旧执行尚未确认。进程退出、工具结束和 Agent 自述完成都是输入，由主机据此判断任务是否结束。

## 4. SQLite、恢复与换手

SQLite 保存任务简报、用户输入、状态变化、标准化运行事件、执行归属、原生会话引用、checkpoint、定时触发记录和结果证据。Codex 与 Claude Code 自己管理原生会话历史。Rudy 从运行时接收并转换事件，控制日志中的输出预览大小；凭证与不必要的环境变量不得进入日志。

任务状态变化和对应日志在同一个事务中写入。主机重启时从已提交的数据恢复任务视图，并核对最后一次执行。等待中的任务保留原等待原因；日志中的「运行中」只说明上次观测到的状态。数据库写入失败时停止接收新的执行和合并请求，并向用户说明；已发出的操作在恢复后核对。

| 场景 | 恢复行为 |
| --- | --- |
| 执行仍活着 | 重新接入已有执行，从已确认的事件位置继续接收 |
| 旧执行已结束，原生会话可用 | 在原设备和工作区用原会话 ID 恢复，保留任务 ID |
| 原会话不存在或拒绝恢复 | 在原工作区新开会话，带入简报、最近的 checkpoint、必要对话和工作区现状 |
| 用户从 Codex 换到 Claude Code | 确认 Codex 已停止写入，再在同一工作区交接简报、最近进展、待处理问题和证据。Claude Code 使用自己的会话 |
| 用户切回 Codex | 优先用 Codex 自己的原会话，并补充换出后发生的变化；原会话失效则走 checkpoint 兜底 |
| 设备离线、登录失效、工作区缺失或执行仍可能存活 | 标出原因并等待处理。只有确认旧执行已停止、工作区可用，才允许启动后续执行 |

Checkpoint 是持久化的进展记录，至少说明已完成事项、当前问题、相关文件或提交、验证结果和建议的下一步。已知结果与推测分开记录。它不快照运行中的工具、审批或进程，也不会回滚文件。没有 checkpoint 时可以从简报和现有工作区继续，但 CLI 要明确提示可用上下文有限。恢复前核对文件与 Git 状态，因为进程可能在最后一次落盘之后又写了文件。

## 5. 任务组、等待与定时

- 串行组按顺序释放成员。前项成功后，下一项拿到它的结果引用。例如审查任务读取修复的 diff 和验证结果。失败或取消会阻塞依赖项，用户可重试、终止剩余任务，或在确认影响后跳过；缺少必需产物的后续任务继续等待。
- 无依赖且工作区隔离的任务可以并行。同一个 worktree 同一时刻只有一个写入者。审查等只读依赖任务，在上游停止写入后读取已确定的改动。
- 任务可等到指定时间，也可等待用户指令。等待条件持久化，等待期间可释放会话进程和执行名额。绝对触发时间持久化，CLI 显示本地时间。
- 例行任务可以启用、暂停或恢复；固定间隔来自持久化的计划。用计划 ID 和预定触发时间标识同一次触发，登记触发与创建任务在同一个事务中完成。主机离线错过多次触发时，只补最近一次，避免重启后出现积压风暴。已有同一例行任务执行中时跳过本次触发。定时器不能替用户确认合并。

## 6. 工作区、证据和合并

- 仅在配置允许的 Git 仓库工作，记录任务的设备、仓库、基线提交、分支和 worktree。独立写任务从明确基线建立独立 worktree；换 harness 和同设备恢复复用原 worktree。Rudy 校验真实路径和符号链接边界。worktree 用于隔离改动，文件及工具权限由相应的执行限制保障。
- 交付至少提供分支或变更标识、diff、验证摘要、未解决问题；有审查任务时还需附审查意见。Runner 能实际观察到的 diff、提交、命令退出状态与 Agent 自述分开显示。缺少完成条件要求的证据时，将缺失项展示给用户，依赖项等待处理。
- 合并由用户确认具体的结果提交和目标分支。确认后检查当前提交是否仍与审查结果一致，以及目标工作区是否适合合并。冲突、目标不可用或已有未提交改动时停止并保留产物。若合并结果在主机崩溃时未能记账，先检查 Git 实际状态再决定下一步。Rudy 不自动推送。

## 7. 远程执行与断线

1. Worker 使用一次性配对凭据，配对后主动建立经身份验证的连接，报告设备身份、已配置仓库和可用 harness。主机可撤销设备资格。主机按用户指定设备或所需能力选择执行位置，不把主机上的本地路径直接传作远程路径。模型凭证留在运行 harness 的机器。
2. 主机先记录执行 ID 再下发。Worker 按执行 ID 识别重复分派，并回报已接收和已启动两个不同事实。Worker 可以重复回传事件；主机按执行 ID 和事件顺序去重。接收确认代表主机已持久化这些事件。
3. 断线期间任务显示正在重连。Worker 如果还持有原执行，重连后报告其身份和最后进展并补发能提供的事件；存在不可补的缺口时明确标记。超过重连等待窗口或连接状态无法判断时，任务转为等待设备，保持原执行归属。
4. 重新配对、主机重启或重试前，核对原执行是否仍在运行。只在确认旧执行已结束时允许恢复或重试。旧执行的迟到事件不能覆盖新执行的状态。该规则避免并发写同一 worktree，不承诺外部副作用严格执行一次。
5. 演示中的远程修复和审查固定在同一台 Worker。合并在该设备上的目标仓库完成，CLI 展示远程证据和结果。会话、未提交文件及工作区不会自动迁到其他机器。

## 8. 上下文、Skills 与长期记忆

- Partner 使用当前请求、近期对话、滚动摘要和相关任务状态。成功生成并保存新摘要后再切换有效上下文；摘要失败时保留原记录，空间不足则提示用户缩小下一轮输入，避免无休止重试。
- 执行 Agent 收到任务简报、相关用户指令和本任务 checkpoint。执行侧沿用已配置的项目指令和 harness 原生 Skills；Partner 只开放协调所需能力。任务日志和工作区是恢复依据，记忆不能把任务标为完成或替用户授权。
- Nowledge Mem 默认关闭。启用后，Partner 能保存用户明确选择保留的决定，并在新任务中按需召回。记忆服务无响应或认证失败时展示简要状态，任务继续依靠本地记录；不自动同步完整会话或仓库内容。

## 9. 验收与五天安排

下面每项以可观察结果验收。自动化测试使用模拟 harness、假时钟与临时仓库；真实 Codex、Claude Code 和第二台机器用于手工演示。本地执行 `npm run check` 和 `npm run test:unit`。

| 日程 | 正常路径 | 必验故障 |
| --- | --- | --- |
| 第 1 天 · 本机闭环 | 从 CLI 委派一次真实 Codex 任务；退出 CLI 后重新连接能看到原任务和结果 | Harness 启动失败有明确原因；主机重启后已存记录可见 |
| 第 2 天 · 恢复与换手 | 原生会话恢复；同任务 Codex → Claude Code → Codex 保留工作区并带上期间进展 | 模拟原会话失效，确认从简报和 checkpoint 继续；旧执行未停止时拒绝换手 |
| 第 3 天 · Git 与编排 | 独立任务可并行；修复和审查按顺序运行；等待、定时与人工合并可用 | 上游失败不放行审查；同一次定时触发在重启后不重复建任务；合并冲突保留分支和改动 |
| 第 4 天 · 跨设备 | 在第二台机器执行，并从主机查看实时进度、结果和原设备位置 | 先断开再恢复连接，核对重复事件和旧执行；状态未知时不会分配第二个写入者 |
| 第 5 天 · 上下文与完整演示 | 长对话续接、原生 Skills、跨任务记忆与端到端演示 | 记忆服务不可用时仍能完成任务；手工演示重启、恢复和交接的区别 |

最终交付还需有从干净环境启动的文档，以及一份可复现的演示步骤，能指出每次故障后的任务状态、判断依据和恢复动作。

## 10. 旧代码迁移与参考

保留现有 pi 原型作为重构前的运行对照。逐段复用 CLI 输入与输出、工作区边界检查及上下文压缩的经验。任务事件存储与原生 harness 会话适配按新职责实现。涉及移除旧入口或替换有意保留的功能时，按仓库规则单独处理；规格不直接改动旧代码或历史。

架构参考 [Ducter 0.0.80](https://github.com/wey-gu/ducter/tree/55ec5b309eef222f3dcc3fdaabd139e17f35efb1)，重点是 Partner/Runner 分工、原生会话恢复与有损交接、Worker 回传。现有原型的摘要实现见 [会话压缩设计](session-compaction.md)。
