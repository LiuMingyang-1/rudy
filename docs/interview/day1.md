# 今天需要学习的概述

Day 1 解决的问题是：用户在终端交代一个任务，交给 Codex 在本机执行，并且**关掉终端不影响任务，重新打开还能看到原任务和结果**。链路是 CLI -> Host -> SQLite -> Runner -> Codex。

核心思路有三点：

1. **CLI 只是视图，Host 才是权威。** CLI 不持有任何状态，只负责提交命令和订阅事件。所有状态变化由 Host 裁决，并且和对应事件在同一个事务里写进 SQLite。这样 CLI 断开、重连、甚至开多个都不会产生分歧。
2. **三种 ID 必须分开。** 任务 ID 代表用户目标，跨重试、跨换手都不变；执行 ID 代表某次具体的领取和运行，用来区分不同尝试、识别迟到事件；原生会话 ID 是 Codex 自己的会话标识，只属于特定 harness 和工作目录。把原生会话 ID 当任务 ID 用，后面一换 harness 就全乱了。
3. **外部 Agent 是不可信的黑盒。** 进程退出码、Agent 自述“完成了”都只是输入，由 Host 综合判断任务是否真的成功。启动失败、卡住、孙进程残留、输出超大，都要有明确的兜底。

另外，Day 1 把“崩溃后不确定的状态”当作一等公民：Host 重启后不假装任务还在跑，也不盲目重跑，而是标为等待并说明原因。

# 面试高频追问：难点、边界条件与兜底

### Q1：CLI 断线重连，或者从“查历史”切到“实时推送”时，怎么保证事件不丢、不重、不乱序？

- **坑**：常见写法是先查一次数据库发历史，再挂内存事件监听推增量。两步交界的瞬间写入的事件，要么漏掉，要么推两遍。
- **解法**：数据库是唯一数据源，内存只传“有新东西了”的无参信号。每个事件先在事务里落盘并拿到单调递增的序号，提交后才唤醒订阅者。每个连接维护自己的游标，被唤醒就查“序号大于游标”的一批。历史回放和实时推送走同一条路径，交界问题自然消失。
- **顺带解决背压**：上一批发送完成才拉下一批，慢客户端不会把 Host 内存撑爆。追平历史时发一个“已追平”信号，任务已结束的话 CLI 可以直接退出。
- **例子**：CLI 断网 10 秒，期间产生 30 条事件。重连时带上最后看到的序号，Host 从那里继续发，用户看到的流是连续的。

### Q2：Host 被 kill -9 后重启，原本运行中的任务怎么处理？为什么不自动重跑？

- **坑（双写）**：为了能整组清理子进程，Codex 跑在独立进程组里。Host 死了，Codex 可能还活着在改文件。如果重启后自动重跑，就会有两个 Agent 同时改同一个目录。
- **解法**：
  - 启动对账：把所有残留的“运行中”统一降为“等待”，原因写明“未确认旧执行已停止”。宁可让用户多点一下，也不制造双写。
  - 目录重叠封锁：派发新任务前检查它的目录和未确认停止的任务是否相等或互为父子，重叠就等待。
  - 防两个 Host 抢同一个库：用一个单独的锁文件持有 SQLite 独占事务。进程崩溃时操作系统自动释放锁，不会像 PID 文件那样残留。
- **取舍**：牺牲一点自动化，换取“绝不并发写同一工作区”这个更硬的保证。

### Q3：把 Codex 这种外部 CLI 当执行器，怎么防“假成功”和“孤儿进程”？

- **假成功**：退出码 0 不等于完成。空跑、配置被忽略、输出提前断掉都可能返回 0。必须同时满足：没有启动错误、退出码 0、拿到了会话开始事件、拿到了明确的回合完成事件，缺一个就判失败并附上错误输出。
- **启动卡死**：设启动超时，一段时间内没拿到会话开始事件就主动停掉并判超时。
- **孤儿孙进程**：Codex 跑测试会拉起一棵进程树。停止时向整个进程组发信号，先温和终止，留几秒宽限，再强杀。
- **停止要确认**：用户点停止，接口只返回“已受理”，不立刻把状态改成已取消；要等进程真的退出、确认不再写文件，才落盘为取消。
- **其他边界**：可执行文件不存在时往它的输入管道写数据会报管道破裂，要接住这个错误交给统一的退出处理；单行输出设长度上限，防止一行巨大的输出撑爆内存。

### Q4：运行中 SQLite 写入失败（磁盘满、权限问题）怎么办？

- **原子性**：更新任务、更新执行、插入事件永远在一个事务里，测试里用触发器注入失败，验证会整体回滚，不会出现“状态变了但没事件”的脏账。
- **熔断（fail-closed）**：一旦写库失败，Runner 进入不可用状态，主动停掉正在运行的 Codex，拒绝后续请求并提示重启对账。原因是：记不了账的情况下继续让 Agent 改文件，事后无法解释发生了什么。

### Q5：Host 只监听 127.0.0.1 就安全了吗？

- **不够。浏览器里的任意网页都能请求本机端口**（跨站请求、DNS 重绑定）。所以拒绝所有带 Origin 头的请求，并严格校验 Host 头；每次启动生成随机 Token，写到仅本人可读的连接文件里，比较时用恒定时间比较防时序攻击。
- **路径越界和检查-使用时间差**：提交时用真实路径校验工作目录在允许范围内；真正启动前再校验一次，防止排队期间目录被换成指向外部的符号链接。工作目录也不能和 Host 自己的数据目录重叠，否则 Agent 能改任务库。
- **最小暴露**：只传必要的环境变量给 Codex；落盘的输出去掉控制字符、把密钥类内容替换成占位符并截断；执行沙箱只允许写目标工作区、禁止联网。
